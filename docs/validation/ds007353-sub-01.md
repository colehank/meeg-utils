# 真实数据验证：HAD-MEEG（OpenNeuro ds007353）sub-01

用 HAD-MEEG 公开数据中 sub-01 的前两个 run 跑通 QC、`had-meeg` 预设和推荐型预设（`eeg-erp`、`meg-erp`），以检查模拟数据测不到的问题。下文的数值都来自这次运行（meeg-utils 0.2.0 开发版，MNE 1.13.2）。

## 1. 数据

| | MEG | EEG |
|---|---|---|
| 系统 | CTF DSQ3500（273 通道 + 28 参考），以 FIF 格式存储，三阶梯度补偿 | Neuroscan（Curry 8），62 通道 + HEO/VEO，EEGLAB `.set` |
| 采样率 / 时长 | 1200 Hz，每个 run 360 s | 1000 Hz，每个 run 约 326 s |
| 数字化 | 只有 3 个基准点，没有头形点；有连续头定位（HLC） | CapTrak 坐标的 62 个电极位置 |
| 其他 | 关联的空房间记录 `sub-emptyroom/ses-20211118` | — |

## 2. 发现的问题与修改

| # | 现象 | 原因 | 修改 |
|---|---|---|---|
| 1 | `Bridging` 报告 EEG 有 197 对桥接电极 | MNE 的电距离阈值是绝对值（16 µV²）；这份 EEG 在 0.5–30 Hz 只有约 7 µV，没有桥接的相邻电极也低于阈值（如 C1–C2，相关仅 0.18） | 候选电极对再用平均参考后 15–30 Hz 的相关复核，≥ 0.98 才算桥接（`min_correlation`、`confirm_band`）。物理短路在各频段都使相关接近 1；未桥接的相邻电极为 0.6–0.8 |
| 2 | 复核后仍有 57–59 对，右后部 8 个电极（P2–P8、PO4–PO8、O2）在两个 run 中都成组桥接，另有额区、中央区沿横排的成对桥接 | 这是真实的采集问题：这些电极对在 15–90 Hz 的相关都在 0.98–0.99，且在两个 run 中重复出现 | 无需修改代码；这是需要告知数据使用者的数据质量问题。推荐 EEG 预设遇到超过 4 个电极的桥接组会停下并说明处理办法，用 `pipe.set_params(bridged__large_groups="bad")` 可改为把它们标成坏道 |
| 3 | PREP 把 C1、Cz 判为坏道 | 检测在记录本身的参考上进行；参考电极在 Cz 附近，C1、Cz 在 1–30 Hz 只有约 0.4 µV（周围 2–3 µV），与其他通道相关性低 | `BadChannels("prep")` 默认先做 PREP 的稳健平均参考（PyPREP `Reference`）再检测，与 PREP 原文一致；原参考下的结果记在 `eeg_before_reference`。加了模拟测试 |
| 4 | Maxwell 坏道检测把 CTF 参考通道（BP3、BR2）标为坏道 | `find_bad_channels_maxwell` 的结果包含参考通道，但参考通道无法插值 | 参考通道不再进入坏道列表，改为记录在 `noisy_references` 并发出警告（三阶补偿会把它们的噪声传给所有通道） |
| 5 | 推荐 MEG 预设在坏道检测时报错 | 没有头形点，`origin="auto"` 无法拟合球心 | `origin="auto"` 拟合失败时，退回 MNE 的默认球心 (0, 0, 0.04) m 并警告（坏道检测、插值、`HeadAlign`、`Maxwell`） |
| 6 | 推荐 MEG 预设被系统因内存不足终止 | ZapLine-plus 在 273 通道、1200 Hz、6 分钟的数据上需要超过 15 GB 内存 | 推荐 MEG 预设改为先降采样到 250 Hz 再去工频（MEGnet 本来就要求 250 Hz）。降采样后 ZapLine-plus 用时 74 s |
| 7 | 用 MEG 合成心电得到 86 bpm，看似正常，但 RR 间期标准差 341 ms | 合成心电的心跳检测漏检、多检严重；原检查只看心率范围 | `HeartRate` 增加"不规则间期比例"判据：偏离中位间期超过 30% 的间期占比 > 10% 时警告 |
| 8 | `meu.Dataset` 把 `sub-emptyroom` 当成被试处理 | 空房间记录在 BIDS 中也是 MEG 记录 | 默认排除空房间记录，除非 `subjects` 中明确列出 |
| 9 | 局部 autoreject 在 MEG 上报 IndexError | autoreject 的 MEG 插值按通道在完整通道列表中的位置索引；CTF 的 misc 通道排在 MEG 之前时索引越界（模拟数据没有这种通道顺序） | `AutoReject` 只在 MEG/EEG 数据通道加参考通道的副本上运行，再把丢弃的 epoch 和修复后的数据写回，其他通道保持不变 |

## 3. 采集质量（QC）结果

- **MEG**：
  - 头动最大 0.81 mm，3 个线圈全程拟合良好；
  - 空房间噪声底 3.08 fT/√Hz，记录比空房间高 4.5 dB；空房间中 MRT54 是离群传感器；
  - 没有 SQUID 跳变；
  - BIDS 描述与数据一致。
- **EEG**：
  - 桥接情况见上表第 2 项；
  - 眨眼约 40 次/分钟；
  - 额中央区工频明显偏强（Fz 处比背景高 28 dB），提示那里的电极接触较差；
  - 肌电约占 6% 的时长；
  - 电极位置的球面拟合半径 97 mm。

## 4. 流程结果

**EEG，`eeg-erp`（`bridged__large_groups="bad"`）**
- 两个 run 用时约 10 分钟（每个 run 预处理约 4.5 分钟，主要花在 PREP 的稳健参考和 RANSAC 上）；
- ICLabel 每个 run 排除 3–4 个眨眼成分和 0–1 个肌电成分，排除的方差占 70–79%；
- autoreject 丢弃 4–6% 的 epoch；
- 合并得到 171 个 epoch；
- 枕区在约 236 ms 有 4 µV 的正波，视觉诱发反应合理。

由于桥接严重，sub-01 的大量 EEG 通道是重建出来的，后部电极尤其如此。对后部成分的分析应谨慎。

**MEG，`had-meeg`**：run-01 预处理用时 443 s（坏道检测 214 s、ZapLine-plus 107 s、ICA 56 s）。MEGnet 在真实数据上运行正常，排除了 1 个眨眼成分（概率 0.875）；心跳成分的概率为 0.625，低于 0.8，没有排除。

**MEG，`meg-erp`（CTF）**
- 每个 run 预处理约 5.5 分钟（坏道检测 153 s、ZapLine-plus 74 s、ICA 36 s），没有检出坏道；MEGnet 排除 1 个眨眼成分；
- 分段阶段，两个 run 都对齐到平均头位置，各偏移 0.37 mm、0.33°；
- autoreject 没有丢弃 epoch，每个 epoch 平均插值 4–12 个通道；
- 合并得到 180 个 epoch；
- 枕区诱发场在 140 ms 达到峰值（RMS 225 fT，基线 22 fT），是典型的视觉反应。

## 5. 资源

- MEG 每个 run（409 通道、1200 Hz、6 分钟，加载后 1.4 GB）：按新顺序运行时内存峰值约 6 GB（高通滤波时）。
- 原顺序下 ZapLine-plus 在 1200 Hz 上需要超过 15 GB，见第 2 节第 6 项。
- EEG 的 PREP 稳健参考加 RANSAC 每个 run 约 50 s（64 通道、250 Hz）。

## 6. 复现

```bash
# 数据：只下载 sub-01 的两个 run（MEG 约 1.4 GB，EEG 约 170 MB）和空房间记录
# https://s3.amazonaws.com/openneuro.org/ds007353/...
meu qc hadmeeg/ --out qc/
meu run --preset eeg-erp --epochs --option "event_id=[video on]" --option tmax=0.8 \
    --set bridged__large_groups=bad --datatype eeg --sources hadmeeg/ --out deriv_eeg/
meu run --preset meg-erp --epochs --option "event_id=[video on]" --option tmax=0.8 \
    --datatype meg --sources hadmeeg/ --out deriv_meg/      # 系统自动识别为 CTF
```
